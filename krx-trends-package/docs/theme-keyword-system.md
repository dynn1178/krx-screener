# 테마키워드 체계

## 왜 만들었나

2026-07-31 ~ 08-26 단 19거래일 동안 447종목에 **140종류**의 테마 표기가 붙었고,
그중 **137종목(31%)이 날마다 다른 테마**를 달았다. 삼성전기 하나가
`AI반도체 / AI부품 / MLCC / 반도체 / 전자부품` 5개를 오갔다.

이러면 1페이지 섹터 막대그래프도, 키워드보드 연속 배지도, 날짜 간 추이 비교도 전부 의미가 없다.
같은 종목이 어제와 오늘 다른 막대에 들어가 있기 때문이다.

그래서 **종목 → 테마를 한 번 정하고 고정**하고, 정말로 흐름이 바뀐 경우에만
승인을 거쳐 바꾸는 구조로 정리했다.

## 일별 분석에서 지켜야 할 것

### STEP 2-1 — 테마는 조회해서 쓴다, 새로 짓지 않는다

STEP 1 에서 종목이 확정되면 **분석을 쓰기 전에** 마스터를 먼저 읽는다.

```sql
select ticker, name, master_theme, master_industry_kw,
       sector_big, sector_small, in_master, locked
from theme_master_lookup
where ticker in ( /* STEP 1 선정 종목 */ );
```

| `in_master` | 할 일 |
|---|---|
| `true` | `master_theme` 를 **그대로** `stock_analysis.theme_kw` 에 넣는다. 그날 뉴스가 다른 흐름을 가리켜도 마스터를 바꾸지 않는다 — 대신 STEP 6-8 에 후보로 남긴다 |
| `false` | 새 종목이다. `sector_small` 을 근거로 표준 테마를 정해 **`theme_master` 에 추가**하고 그 값을 쓴다 |

새 종목을 추가할 때:

```sql
insert into theme_master (ticker, name, theme, industry_kw, sector_big, sector_small, source, first_seen, note)
select 'XXXXXX', '종목명', '표준테마명', '산업키워드',
       r.sector_big, r.sector_small, 'manual', 'BASE_DATE', '최초 등장 시 배정'
from sector_ref r where r.ticker = 'XXXXXX';
```

`industry_kw` 는 `sector_small`(업종소 166종) 을 기본값으로 삼되, 더 좁고 정확한 표현이
있으면 그쪽을 쓴다. 예: 업종소가 `반도체 관련장비 및 부품` 이어도 실제로는 `반도체테스트소켓` 이면
후자를 쓴다.

**테마와 업종은 다른 축이다.** 업종은 회사가 무엇을 파는지(정적), 테마는 시장이 지금 무엇으로
묶어 부르는지(동적)다. 현대건설의 업종은 `건설` 이지만 원전 수주로 움직인 날에도 테마는
`건설` 로 둔다 — 그날의 원인은 `issue_kw` 와 `issue_note` 가 담는다.

### STEP 6-8 — 다르게 봤으면 후보로만 남긴다 (신규 · 필수)

그날 뉴스 근거로 판단한 테마가 마스터와 다르면, **마스터는 그대로 두고** 기록만 한다.

```sql
insert into theme_drift_candidate
  (base_date, ticker, master_theme, proposed_theme, proposed_industry_kw, evidence)
values
  ('BASE_DATE','005930','AI반도체','밸류업주주환원','메모리반도체',
   '자사주 매입 발표가 주가를 움직인 직접 원인으로 보도됨')
on conflict do nothing;
```

`evidence` 는 **왜 다르게 봤는지 한 줄**이다. 나중에 승인 판단의 근거가 되므로
"다름" 같은 말은 쓰지 않는다.

후보를 남기는 기준: 그날 주가를 움직인 원인이 마스터 테마와 **다른 흐름**에 속할 때만.
단순히 이슈가 특이한 것은 후보가 아니다 — 그건 `issue_kw` 가 담는다.

## 변동 알림과 승인

### 언제 알림에 뜨나

`theme_drift_alert` 뷰가 세 조건을 모두 만족할 때 `status = 'ready'` 로 올린다.

1. **지속 기간 30일 이상** — 첫 불일치와 마지막 불일치 사이가 한달 이상
2. **불일치 3회 이상**
3. **불일치 비율 50% 이상** — 그 기간 그 종목이 스크리닝에 걸린 날 중 절반 넘게 어긋남

하나라도 못 채우면 `watching`(관찰 중), 마스터가 `locked = true` 면 `locked`.

조건 2·3 이 있는 이유: 한 종목이 40일 간격으로 딱 두 번 다르게 잡힌 것은 흐름이 바뀐 게 아니라
그날의 예외다. 비율 조건이 없으면 예외가 마스터를 흔든다.

### 어떻게 바꾸나 — 사용자가 요청할 때만

> **자동으로 바뀌는 일은 없다.** 알림에 `ready` 로 떠 있어도 마스터는 그대로다.

사용자가 `"삼성전기 테마 변경 승인해줘"` 처럼 요청하면:

```sql
select approve_theme_drift(
  p_ticker      => '009150',
  p_new_theme   => 'AI반도체',        -- 생략하면 ready 후보 중 최장 지속 건
  p_approved_by => '준희',
  p_reason      => 'AI 서버용 MLCC 비중 확대로 반도체 흐름에 묶임'
);
```

이 함수가 하는 일:
1. `theme_master` 갱신 (`source = 'approved'`)
2. `theme_master_history` 에 이전값/새값/사유/승인자 기록
3. 해당 종목의 `theme_drift_candidate` 정리 — 다음 불일치부터 새로 센다

거부되는 경우: 종목이 마스터에 없을 때, `locked = true` 일 때,
새 테마가 `theme_catalog` 에 없을 때.

**과거 데이터는 소급하지 않는다.** 승인 이후 날짜부터 새 테마가 적용된다.
과거까지 바꾸려면 별도로 지시해야 한다.

### 테마를 못 바꾸게 잠그려면

```sql
update theme_master set locked = true, note = '분류 확정' where ticker = '005930';
```

## 정규화가 이미 한 일

기존 이력 958행의 `theme_kw` 를 표준 테마로 통일했다. **원본은 `theme_kw_raw` 에 보존**돼 있으므로
되돌릴 수 있다.

- 140개 표기 → **50개**(표준 47 + 메커니즘 3)
- `2차전지` ← `이차전지`
- `제약바이오` ← `바이오` `mRNA바이오` `바이오신약` `바이오헬스` `헬스케어`
- `로봇·피지컬AI` ← `로봇` `로봇자동화` `휴머노이드` `휴머노이드로봇` `피지컬AI` `피지컬AI로봇`
- `방산우주` ← `방산` `우주항공` `방산드론` `드론`
- 시딩 이전에 달랐던 172건은 `theme_drift_candidate` 에 자동 등록돼 알림에서 관찰 중이다

### `keyword_board` 이상치 가드 (변경됨)

가격제한폭(±30%)을 넘는 행은 액면병합·분할로 기준가가 어긋난 데이터 오류이므로
**집계에서 자동 제외**된다. 예전처럼 해당 종목의 `theme_kw` 를 비워서 빼는 우회는 더 이상
하지 않는다 — 종목은 원래 소속 테마에 그대로 두고, 뷰가 알아서 거른다.

## /trends 탭

### 화면

기간 선택(1주 / **1개월 기본** / 6개월 / 1년), 지표 선택(거래대금 / 등락률),
축 눈금(로그 기본 / 선형) 위에 선 그래프 3개가 있고, 각 그래프 **우측에 그 키워드의 구성 종목이
거래대금 내림차순**으로 붙는다. 범례를 클릭하면 우측 패널이 그 키워드로 바뀐다.

| 그래프 | 무엇을 고르나 | 왜 |
|---|---|---|
| 거래대금 상위 테마 10 | 기간 거래대금 합계 상위 | 자금이 어디에 머물렀나 |
| 상승폭이 큰 산업키워드 5 | 기간 평균 등락률 상위 | 테마보다 좁은 단위에서 무엇이 실제로 올랐나 |
| 꾸준히 상승중인 테마 5 | 상승일 비율 상위 (동률 시 누적 등락률) | 한 방이 아니라 지속성 |

2·3번은 최소 등장일 조건이 있다 — 1주는 2일, 1개월은 3일, 그 이상은 5일.
하루 반짝한 키워드가 상위를 차지하는 것을 막는다.

**거래대금 축은 로그가 기본이다.** 1위 테마와 10위 테마의 거래대금이 두세 자릿수 차이라
선형으로 두면 1위가 나머지를 바닥에 눌러 평평하게 만든다.

**선은 결측일에서 끊긴다.** 그날 그 키워드에 걸린 종목이 없었다는 뜻이며 0으로 잇지 않는다.

### 데이터

전부 `get_trend_board(p_days)` RPC 하나로 내려온다.

```sql
select get_trend_board(30);
```

반환 구조: `{from, to, days, dates[], topTradeValue[], topGainerIndustry[], steadyRisers[]}`.
각 계열은 `{key, points[{date, tradeValue, changePct, mentions}], topStocks[{code, name, tradeValue, lastChangePct, days}], ...}`.

### 화면과 테이블 대응 (추가분)

| 화면 영역 | 읽는 곳 |
|---|---|
| 키워드 추이 3종 선 그래프 | `get_trend_board()` ← `theme_trend_daily` · `industry_trend_daily` |
| 그래프 우측 구성 종목 패널 | `get_trend_board()` 의 `topStocks` ← `keyword_board.stocks` |
| 테마키워드 변동 알림 | `theme_drift_alert` 뷰 |

## 자주 하는 실수

- **마스터를 조회하지 않고 테마를 새로 짓는 것.** 이 체계 전체가 무의미해진다. STEP 2-1 은 선택이 아니다.
- **drift 후보를 남기지 않고 마스터를 직접 UPDATE 하는 것.** 이력도 근거도 남지 않는다.
- **`theme_catalog` 에 없는 테마를 쓰는 것.** 새 테마가 필요하면 카탈로그에 먼저 등록한다.
- **업종을 테마로 쓰는 것.** `sector_small` 은 `industry_kw` 의 기준값이지 `theme_kw` 가 아니다.
- **메커니즘 라벨을 테마로 쓰는 것.** `수급주도` 는 `issue_kw` 에 쓰고, `theme_kw` 는 그 종목의 실제 소속을 넣는다.
